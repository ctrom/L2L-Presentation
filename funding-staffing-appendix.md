# Appendix: Funding Justification & Staffing Plan
### Supporting documentation for the $3.8M funding request — TechNovation AI Clinical Decision Support
 
---
 
## Cost Bucket 1: AI Model Licensing & Customization
 
| Field | Detail |
|---|---|
| **Amount** | $1.2M |
| **Covers** | Licensing fee for existing third-party clinical AI model + configuration/customization work to adapt it to TechNovation's data formats and clinical use cases |
| **Basis for estimate** | Licensing fee (upfront) + customization services engagement (vendor specialist hours over build phase) |
| **Why this approach** | Buying proven technology vs. building proprietary ML from scratch — lower cost, lower risk, faster time to market |
| **Alternative considered** | Build in-house — rejected: multi-year timeline, much higher cost, higher technical risk |
| **Panel-ready framing** | "This is the cost of speed — paying for a head start, not reinventing something that already exists." |
 
---
 
## Cost Bucket 2: Integration Engineering
 
| Field | Detail |
|---|---|
| **Amount** | $700K |
| **Covers** | Engineering work connecting the licensed AI model into TechNovation's existing platform — APIs, data pipelines, UI/workflow embedding |
| **Basis for estimate** | ~6-month integration timeline × loaded cost of dedicated engineering team |
| **Why this approach** | Sized to existing platform architecture — this is an upgrade, not a rebuild |
| **Alternative considered** | Standalone new product — rejected: higher adoption barrier for existing clients |
| **Panel-ready framing** | "The cost of making it invisible to the user — the harder we work here, the less our clients have to change." |
 
---
 
## Cost Bucket 3: Data Infrastructure & Compliance
 
| Field | Detail |
|---|---|
| **Amount** | $500K |
| **Covers** | HIPAA-aligned data pipeline (ingestion, storage, access controls) + clinical validation study costs + initial compliance/legal review |
| **Basis for estimate** | Split roughly between infrastructure build (data engineering) and one-time compliance/audit fees |
| **Why this approach** | Compliance addressed from month one, in parallel with build — cheaper than retrofitting later |
| **Alternative considered** | Defer compliance work to post-pilot — rejected: highest-risk, highest-cost-if-wrong item on this list |
| **Panel-ready framing** | "We pay for this up front because the alternative is paying far more later — in delays, fines, or a failed audit right before a client signs." |
 
---
 
## Cost Bucket 4: Core Team (12 months)
 
| Field | Detail |
|---|---|
| **Amount** | $1.1M |
| **Covers** | Fully loaded compensation (salary + benefits + overhead) for the core project team across build and pilot phases |
| **Basis for estimate** | Loaded cost of 4 core roles + supporting engineers/specialists over 12 months |
| **Why this approach** | See staffing plan below — this number blends existing (reassigned) staff and net-new contractor spend |
| **Note** | This is the bucket most sensitive to the staffing mix decision — worth flagging to the panel that not all of this is "new" money |
| **Panel-ready framing** | "This reflects a lean core team, deliberately not overbuilt ahead of revenue." |
 
---
 
## Cost Bucket 5: Pilot Support Contingency
 
| Field | Detail |
|---|---|
| **Amount** | $300K |
| **Covers** | Buffer for pilot-phase surprises — added clinician training time, site-specific integration issues, minor scope adjustments from early feedback |
| **Basis for estimate** | ~8% of total budget — standard contingency range for bounded (not open-ended) technical risk |
| **Why this approach** | Plan for the unexpected now rather than return for supplemental funding later |
| **Alternative considered** | No contingency line — rejected: removes flexibility, signals overconfidence to the panel |
| **Panel-ready framing** | "Not because we expect problems — so a small problem doesn't turn into a funding request in month nine." |

## Staffing Plan
 
| Function | Staffing Source | Rationale |
|---|---|---|
| **Core leadership** (Christopher, Margie, Ashley, Dane) | Existing staff, reassigned/dedicated to this project | Already know TechNovation's platform, clients, and internal processes — fastest, lowest-risk choice for leadership roles |
| **AI model customization** | Contractor / vendor specialists (from the licensing partner) | Specialized expertise reduces ramp-up time and avoids a costly in-house learning curve on a new technology |
| **Integration engineering** | Existing platform engineers + 1–2 contract engineers for surge capacity | Existing engineers know the codebase; contractors add short-term capacity without permanent headcount commitment |
| **Data infrastructure & compliance** | Mix — existing IT/compliance staff for platform work, external HIPAA/healthcare-AI consultant for specialized sign-off | Specialized regulatory expertise is worth buying rather than building in-house for a first project |
| **Clinical validation (pilot)** | Pilot clients' own clinicians, coordinated by Margie | Reinforces co-design narrative and directly supports the adoption-resistance mitigation |
 
**Key talking point if pressed:** This is a hybrid staffing model — built on existing staff and platform knowledge where that's the advantage, with specialized contractors/consultants brought in only where outside expertise is genuinely faster or lower-risk than building it in-house. This keeps the core team lean and avoids overhiring ahead of pilot revenue.
